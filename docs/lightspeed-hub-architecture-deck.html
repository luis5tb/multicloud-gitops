—— WHAT HAD TO BE BUILT

The hub had no A2A and no identity — both are built and live

  • A2A adapter — Go service in lightspeed-hub (a2a-adapter/): A2A task → AgenticRun, status → A2A events, own agent card (protocolVersion 0.3).
  • Spokes see the caller — every kube read is made with Token U for the caller's sub, through a per-spoke Praxis gateway.
  • lightspeed-agentic-operator, gateway credential mode — sandbox kubeconfig points at the spoke gateway with the run token; no spoke ServiceAccount, no spoke-management kubeconfig.
  • GitOps for all of it — charts lightspeed-hub, praxis-proxy (hub + spoke gateways) and keycloak-oidc (exchanger clients, roles) in this repo.

—— LEG 1 · ACME → MAS

A2A IDs are the durable spine — Temporal is MAS's engine, not the protocol

Layer / IDMeaning and persistence
A2A contextIdConversation, owned by principal + blueprint; Mongo maps it to a MAS session reused across turns
A2A taskIdOne submitted turn; task record holds status, message ID, session + workflow handle
A2A messageIdOne submission/follow-up; duplicate delivery returns the existing record — no second turn
Temporal a2a-<taskId>Parent SessionWorkflow, REJECT_DUPLICATE; a graph node may call out via A2A (the Hub Cluster Investigator)
  • Token A is sealed — Fernet (Vault mao-run-credentials); never plaintext in logs or workflow inputs.
  • Downstream hub task ≠ MAS task — the hub task maps to one AgenticRun; MAS streams it for up to 1200 s.

—— LEG 2 · MAS → LIGHTSPEED HUB

The hub gateway mints H; the adapter creates the run as the caller and mints R

  • A → H at Praxis — delegate() as client mas-a2a; the adapter never sees A, so no protected-A handoff is needed.
  • Run created with H — the hub kube API sees user keycloak:<sub> in group …:agenticrun-creator; the adapter's SA cannot create runs.
  • H → R in the adapter — as client lightspeed-hub-a2a (lifespan 1800 s); R stored in ls-run-token-<uid>, key token-a.
  • Requester × target — ValidatingAdmissionPolicy on spec.targetCluster for the creator's group.
  • Agent card passthrough — Praxis serves the adapter's own card (protocolVersion 0.3); no static card to drift.

—— LEG 3 · THE ARTIFACT

One kubeconfig is the whole run-leg contract

clusters:
  - name: spoke-via-gateway
    cluster:
      server: https://praxis-spoke-hub.praxis-proxy.svc.cluster.local:8443
      certificate-authority: /var/run/secrets/praxis-gateway/ca.crt
users:
  - name: requester
    user:
      tokenFile: /var/run/secrets/run-identity/token-a   # the run token R
contexts:
  - name: spoke
    context: { cluster: spoke-via-gateway, user: requester }
current-context: spoke
  • The gateway is the server — no subPath on the token mount, so a renewed R appears in place.
  • The B1 spike passed — the pinned Praxis proxies the kube API reads an investigation needs, so the fallback (adapter brokers U) was never needed.

—— DECISION · PHASE 2 MATRIX

B1 won — and the run token R replaced the parked A

Not needed

A · adapter brokers U

Fallback if Praxis could not proxy the kube API. The spike passed, so it was never built.

Implemented

B1 · gateway at the spoke API

Spoke gateway mints U per call; no U at rest, no refresh loop. The sandbox carries R (30 min, usable only at the gateway), not the caller's A.

Rejected

B2 · sandbox self-serve

Both halves of the exchange inside the run's blast radius, for no gain.

Upstream default

C · operator SA tokens

Stock behaviour outside gateway mode: standing kubeconfig, per-run SA, no caller identity at the spoke.

Invariant kept: the token the spoke accepts speaks for the caller (same sub). What crosses the request→run gap is R, derived from H, never the caller's own A.

—— RENEWAL & RESUME

R outlives A because an exchanged token takes the exchanger's lifespan

TokenLifetimeRenewed by
SVID (workload)Short; rotated in placeWorkload API — automatic
A (caller)300 sACME re-mints: 401 → mint + resend; AUTH_REQUIRED → follow-up on the same task
H (run creation)300 sHub gateway exchanges the fresh A
R (run credential)1800 sAdapter exchanges the fresh H and rewrites ls-run-token-<uid>
U (spoke reads)300 sNothing — minted per call by the spoke gateway
  • MAS mailbox — the adapter's auth-required lands on the same task/context with a new message ID; no new run, no second submit().
  • Open — renewal for steps longer than one R, across long approvals.
  • Safety ≠ renewal — 403 is a denial; fresh credentials never revive terminal tasks or bypass approvals.

—— WHAT LIVE TESTING PROVED

Done means fails closed — proven with real requests

  • End to end — an ACME request ran to Analyzed=True Succeeded; R stored with aud praxis-spoke-gateway, azp lightspeed-hub-a2a, 1800 s.
  • Each token works at one place only — H ⇒ agenticrun-creator, U ⇒ reader; A and R get 401 at every kube API.
  • Keycloak rules — exchange audience must be an existing client; the exchanger must be in the subject's aud; azp becomes the exchanger; fullScopeAllowed: false or audience-resolve leaks audiences into A.
  • Praxis quirks — Basic auth without URL-encoding (alphanumeric secrets); role: user workaround; IPv4-only DNS sidecar; NetworkPolicy must allow DNS pod port 5353.
  • Fail-closed paths seen live — wrong azp ⇒ 403 at the spoke gateway; missing finalizer UPDATE clause ⇒ admission denied; expired A ⇒ investigation stopped.
