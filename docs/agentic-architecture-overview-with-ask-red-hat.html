Agentic pattern: cluster investigations and Ask Red Hat

ACME asks the hub-hosted MAS orchestrator; MAS delegates Red Hat knowledge questions to the external Ask Red Hat agent, or cluster investigations to lightspeed-hub over A2A, through the Praxis hub gateway. Ask Red Hat replies to MAS; it does not call Praxis. For investigations, the lightspeed-agentic-operator runs a sandbox that reads the cluster through the Praxis spoke gateway. Keycloak (realm rca) issues and exchanges every token on the way, so each hop carries a token scoped to exactly that hop, always for the same sub. The step-by-step token walkthrough is in agentic-e2e-token-flow.html.

Token A · caller (acme-agent) Token H · run creation Token R · run credential Token U · spoke reads MAS → Ask Red Hat · outbound A2A Keycloak token endpoint identity / LLM / control Blue-bordered boxes: Praxis instances

Two downstream destinations, one hub-hosted orchestrator: MAS calls Ask Red Hat externally for knowledge questions, and Praxis → lightspeed-hub for cluster investigations. Ask Red Hat is separate from Red Hat SSO (the identity provider shown above). Only the investigation branch traverses Praxis and uses the A → H → R → U chain below.

The four investigation tokens

Rule: each token's audience is the client that exchanges or consumes it next, so every exchange asks for one audience, and Keycloak's "exchanger must be in the subject token's aud" holds by construction. All four carry the same sub (the caller: token exchange keeps the subject and only changes azp, aud, groups and lifetime), so every hop acts on behalf of the same identity.

Components

ACME agent

Chat agent (ns acme-agent). Answers Red Hat questions by delegating to MAS.

  • Keycloak client acme-agent, authenticated with its SPIFFE JWT-SVID (no static secret)
  • Calls MAS A2A with Token A
  • LLM through LiteLLM

MAS (mao)

Multi-agent orchestrator running on the hub cluster. The A2A endpoint is the pattern's front door.

  • MAS A2A validates the inbound credential and seals it (Fernet) into the Temporal task
  • mas-worker delegates knowledge questions to Ask Red Hat, or investigations to "Hub Cluster Investigator" through Praxis
  • Forwards the execution-context credential to the selected agent; Gemini on Vertex AI

Ask Red Hat agent (external)

Red Hat's hosted knowledge and documentation agent, called by MAS over A2A.

  • MAS initiates the outbound call with the forwarded Red Hat SSO credential
  • Returns answers to MAS for the response to ACME
  • Does not call Praxis or use the cluster-investigation token exchanges

Praxis hub gateway

praxis-proxy Deployment and Route (ns praxis-proxy).

  • Validates A (Keycloak, or Red Hat SSO as alt issuer), azp allow-list
  • RFC 8693 delegation as mas-a2a: A → H
  • Routes A2A to the adapter; serves the adapter's agent card publicly

lightspeed-hub A2A adapter

Translates A2A tasks into AgenticRuns (repo lightspeed-hub).

  • Creates the AgenticRun with H (the user's identity)
  • Exchanges H → R as lightspeed-hub-a2a; stores R in ls-run-token-<uid>
  • Watches runs with its own ServiceAccount; renewal via A2A auth-required

lightspeed-agentic-operator

Runs the investigation (repo lightspeed-agentic-operator, gateway credential mode).

  • Agent default, LLMProvider vertex, ApprovalPolicy cluster
  • Creates the sandbox pod with a kubeconfig pointing at the spoke gateway, token = R
  • No spoke ServiceAccount, no spoke-management kubeconfig

Praxis spoke gateway

One per spoke: praxis-spoke-<id> (here praxis-spoke-hub).

  • Validates R (aud praxis-spoke-gateway, azp lightspeed-hub-a2a)
  • Per call, exchanges R → U as praxis-spoke-gateway (aud per spoke)
  • Fixed upstream: the spoke API, TLS verified; IPv4-only DNS sidecar

Keycloak (RHBK)

Realm rca, imported by charts/all/keycloak-oidc.

  • Issues A; performs the three exchanges
  • Client roles projected into groups per audience
  • Issuer for OpenShift Native OIDC on the kube APIs

Kube APIs

OpenShift Native OIDC maps sub → keycloak:<sub>, groups → keycloak:<group>.

  • Hub: H's group may create AgenticRuns (plus a ValidatingAdmissionPolicy on the target)
  • Spoke: U's group gets cluster-reader and cluster-monitoring-view
  • A and R are rejected (401)

Vault, ESO, Red Hat SSO, Vertex

Supporting services.

  • Vault + External Secrets deliver every client secret and the Vertex credentials
  • Red Hat SSO: alternative issuer (aud api.ask_red_hat) for SSO callers and Ask Red Hat
  • Vertex AI: one credential and model for MAS and the sandbox
